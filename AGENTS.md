# Documentation

The software is beta. Configuration and user-facing incompatibilities are expected.
In every PR, describe the current state without migration, upgrade or backward-compatibility prose.
Keep each fact in one reference location and link to it elsewhere. Preserve behavior, defaults,
constraints, protocol details, tested capabilities and useful screenshots; shorten prose where possible.
Keep documentation user-facing, without implementation-source or unverified-camera inventories.
Use one screenshot per view, without appearance-mode variants or separate light/dark instructions.
